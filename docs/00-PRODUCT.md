# Product scope: TogetherServer v1

Live save sharing has an owner-only staging fixture action, bounded durable attempts, fixed completion requests and a separate six-stage acceptance matrix per game. Game-specific candidates now connect completion to sealed immutable copies, but Valheim, Java, Bedrock, Factorio and Terraria remain disabled until each passes its own real completion/copy/transfer/load/change/restart checks. Post-Stop sharing and manual guarded takeover continue unchanged. A pending Bedrock hold automatically attempts exact-run resume after app restart, stays visible until a fresh acknowledgement, and blocks another capture; the owner can retry the fixed resume action.

The owner-only **Test a copy in the game** guide can prepare a completed backup or currently verified received save into fresh disposable storage. It records exact copy identity and preparation app/installed game versions, with separate optional owner-reported game version and load/change/restart results. Valheim can use its reviewed driver with a fresh password, isolated save root and new ports; fixture trials exercise process control only. Other games or missing binaries use manual steps. Nothing grants takeover authority or certifies real-game support.

## Goal

Let the owner host a dedicated game server on a Windows PC and let a small, known group of friends see its status and request approved actions from their own Windows PCs. Valheim was first; Minecraft Java, Minecraft Bedrock, Factorio, and Terraria now have built-in local Host drivers. Factorio and Terraria remain previews with automatic crash restart disabled. Terraria has no trusted player count, so its Friend and automatic Stop remain blocked. An advanced custom-game profile lets the local owner supply protected Start, Status/players, and Stop scripts without widening the Friend API. Real Minecraft, Factorio, and Terraria joins and saved-world restart checks remain acceptance gates. Keep the program understandable: one installable app with Host and Friend modes, a bundled GUI, approved actions, and local settings. No cloud control plane or separate database service.

## People and modes

- **Owner / Host mode:** configures a game server and its world, starts or stops it, and invites Friends. Minecraft setup can find an existing server or install a fresh official server after the owner accepts its terms in the app. Valheim setup includes a protected game password. A Custom game profile runs only owner-authored/reviewed PowerShell actions under the Host's Windows account. Installed paths, ports, multiple servers, and remote Stop safety live in secondary settings. The Host app supervises game processes and shows honest status and errors.
- **Friend mode:** each friend runs the same app on the PC used to play. Each pasted server code creates a distinct credential that initially grants only that server. The Host may later assign the PC to zero, one, or several saved servers and may attach a separate owner-defined UTC access deadline to that PC. The app sends authenticated heartbeats, displays only assigned Host servers and their reported online-player counts, and requests only actions the owner grants while owner access remains active. When that exact assigned server has a separate View logs grant and advertises the log capability, the app can show a bounded sanitized Valheim, Minecraft Java, or Minecraft Bedrock tail from only its exact active run; Start and Stop do not imply log access. Owner access expiry does not revoke or delete the credential or assignments, so only the local owner can extend or clear it.
- **Owner playing locally:** the Host sees the same server-reported count as Friends. No local game-process path or indicator is used for automatic or remote Stop.
- **Owner joining another Host:** Hosting and Friend connection are concurrent capabilities in one app process. Opening a Friend connection must not stop the owner's managed server, disable its companion listener, or interrupt existing paired Friends. The visible Host and Join pages are navigation, not mutually exclusive runtime roles.
- V1 requires the companion app for anyone who wants remote controls. Console and unpaired players are still covered by a reliable server count for Stop safety; they do not need a player ID entered in TogetherServer.

## V1 user flow

1. The per-user installer creates a searchable Start-menu shortcut and may preselect Host or Join plus opt-in sign-in/tray preferences. Every installer choice is optional and reversible; choosing nothing leaves the in-app first-use choice unchanged. Setup never configures or starts a game, copies a world, or enables a public listener. On first use, the owner chooses Host or Join. Host uses a Game, World, Server app, and Review guide. For Valheim, the owner chooses a new world or a copied existing world, enters a game password, then saves and starts. Factorio preview copies one owner-selected save ZIP into a per-profile managed directory and requires an owner-installed `factorio.exe`; the original save is never hosted from or overwritten. Game installation and terms remain the owner's actions.
   Terraria preview follows the same copy-first rule for an owner-selected `.wld` and requires an owner-installed `TerrariaServer.exe`. The app never starts from the original world.
2. The owner copies the saved server's current code privately. The first use creates it and enables the secure Friend connection immediately. The code stays available for any number of new PCs until the owner deliberately replaces it; there is no pairing timer or device limit. Optional local approval can hold each new PC until the owner approves it. Replacing a code and removing old access is separate from removing one connected PC.
3. A Friend pastes the server code. It includes the Host address, initial server identity, shared secret, and full Host TLS fingerprint. The Friend app verifies the pinned identity and saves its own revocable access. Each PC starts with only that server assigned; the Host can reassign the PC to any combination of saved servers. The local owner can set, extend, or clear a bounded per-PC access deadline from the connected-PC card using reviewed durations or an explicit validated UTC value with a local-time preview. At the exact deadline, every authenticated companion read or action returns typed `AccessExpired`, while the saved access, assignment, and permissions remain available to the local owner. Friend mode presents that state as owner-ended access, explains that the Host can extend or clear it, and preserves the saved connection. Approval pending, renewable access expiry, and owner removal remain independent states. Friend mode can rename or forget a saved Host; reachable Forget first asks the Host to remove this PC, while offline Forget removes the protected local access and warns the user to ask the Host to remove the stale PC.
4. A permitted friend may request Start for a specifically assigned server. The Host serializes requests, reports a named driver-declared port conflict before the more general concurrency limit, checks save-folder conflicts and actual local port availability, starts only the saved game server program through its built-in driver, and reports Starting until it observes the driver's local readiness signal. A duplicate request cannot launch a second process for the same save folder. Setup gives a non-blocking warning for overlapping saved port plans and may suggest a non-overlapping configured port; Start remains authoritative.
5. A failed Start never stops another server automatically. When the failure is a managed port conflict, the Friend may deliberately choose to replace the conflicting server without access to or Stop permission for that other server. The Friend must have Start permission for the requested server, remote controls must be enabled, every conflicting server must be Ready with exactly zero reported players, and no Host- or Friend-added shutdown time may still be active. Host repeats the zero-player check inside the lifecycle gate immediately before graceful Stop, then starts the requested server only after the conflict exits. The response identifies only the server name and shared ports, not unassigned connection details.
6. A permitted friend may request Stop only when the Ready game server returns a fresh online-player count of zero. Host asks the same built-in driver for the count again immediately before the graceful stop signal. A positive, missing, malformed, partial, or unknown count denies remote Stop. The owner can request local Stop independently, including while players are online.
7. The owner can turn **remote controls off** without stopping a running game. Host rejects new remote Start, Stop, Restart, replacement, and timer-extension requests immediately, keeps an authenticated read-only heartbeat/status channel so connected Friend apps can display the disabled notice, and shows it after an offline Friend reconnects. Revoking a Friend device invalidates its credential and is shown as Revoked on its next request.

## Server chat

Each saved server has one room for discussion and issue reports. The owner can add or remove an assigned Friend PC from that room independently of lifecycle and log permissions. The room stays available while a game server is stopped or remote Start/Stop is paused. Messages have a 500-character limit and Windows-protected local copies retain at most 200 messages from 30 days. Connected PCs reconcile their copies over the existing Host companion route, regardless of whether the owner chose direct Internet, private mesh, or advanced address. A Friend may queue up to 20 drafts while disconnected; they are sent when authenticated Host access returns. A Host can rebuild a lost chat log from messages previously signed by its durable chat key and returned by a connected Friend. Existing copies cannot be recalled from a removed PC. Current chat cannot deliver a new message directly between Friend PCs while the Host listener is offline; that requires an independently reachable, authenticated peer route.

## Auto shutdown

The development app offers a repeatable **Run rehearsal** with another owned Windows PC. The Host prepares a synthetic disposable server; normal pairing, room membership, Receive grants and local consent remain required. The test PC runs connection, two-way chat and verified transfer/receipt checks with one action. The bounded redacted report distinguishes loopback, owner-reported same LAN and owner-reported separate network, and leaves unobserved outside TCP and human game checks unverified.

- The owner sets an idle duration in minutes and can disable auto shutdown. Default it to **off**, and keep the missing real-game acceptance visible before recommending it for a valued world.
- Server-reported player counts are the only occupancy signal. Valheim prefers its local query; a non-Crossplay no-reply case may use only a complete connection history from TogetherServer's own run log. A malformed query or incomplete log sequence is Unknown, never zero. Host and Friend game-running checks and paths do not exist.
- When enabled, each Ready zero-player server owns a Host-generated shutdown deadline shown as the same live countdown on its Host card and every assigned Friend card. A positive or Unknown count cancels that deadline, but added minutes remain saved for the current managed server run and are applied when a later exact-zero observation starts a fresh idle window. The Host may add an entered number of minutes while the reliable count is zero or positive. An optional per-server `CanExtendTimer` permission, off by default, lets a Friend add only the Host's fixed increment up to the configured maximum for that server run, including while players are online. When no deadline exists, both cards show the count-based timer reason and any saved time. Stopping/restarting the server, changing the idle wait, disabling automatic shutdown, lifecycle recovery, or a Host app restart clears the in-memory extension state; a Host app restart starts a fresh idle window rather than counting unobserved time.
- At expiry, Host rechecks the driver's current count under the lifecycle gate and stops only if it is still exactly zero. Fixture coverage is not real-game acceptance; each real built-in game still needs a tested count transition, idle window, graceful stop, and recognizable save/restart result before the owner relies on automatic shutdown for a valued world.
- A long suspend/resume polling gap invalidates readiness, player-count evidence, and any active deadline before a fresh driver observation. It preserves already-added time for the exact managed run instead of counting unobserved sleep as verified idle time. An independent opt-in setting may make a scoped Windows system-required power request only while an exact managed server process is running; deliberate sleep, shutdown, and external interruption remain possible.
- Never force-kill a real world as a normal idle action. Surface timeout/failure and leave the process/world state Unknown when a graceful stop cannot be verified.

Per-server maintenance keeps status visible while denying remote Start, Stop, Restart, replacement, and timer extension. A bounded owner message explains the maintenance state. A structured 500-event/30-day activity feed coordinates pairing, permissions, remote operations, lifecycle, player-count transitions, countdowns, recovery, route changes, backup work, and expiring credentials without storing secrets, Custom scripts, passwords, player identities, or player IP addresses. The Attention Center groups repeated event kinds and links reviewed categories to their owning server or Settings surface; activity content never supplies a command. Important events may also appear through native tray notifications.

## Settings and honest status

The compact Host **All servers** overview derives its rows from the existing snapshot, backup status, recovery and reviewed Attention categories. It sorts action-needed rows first while preserving the owner's selection. Each row distinguishes unavailable or stale player evidence, missing backup data, no completed backup and the latest failed attempt, with the exact current deadline when a fresh zero-player run has one. Actions navigate to the existing owning workspace. No summary, old session statistic or warning grants Stop, recovery, replacement or takeover authority.

- `maxConcurrentServers` is an owner-set positive count, default 1. It limits only TogetherServer-managed processes. Each running world needs a distinct save location and game ports.
- Configure idle minutes, game executable path, world/profile, server name, port, remote-control toggle, per-friend server assignments, Start/Stop/Extend/View-logs permissions per assigned server, and a nullable owner access deadline per paired PC. The deadline editor shows no deadline, an active local date/time with relative text, or expired; presets and Clear map exactly to the reviewed backend contract, while Advanced accepts only an explicit future UTC value no more than 365 days away and previews its local conversion before Save. Deadline changes do not alter assignments or permissions. **Status only**, **Can start**, and **Trusted helper** permission presets atomically set all four global permissions for every assigned server and clear per-server exceptions; mixed or individual choices remain Custom. View logs and timer extension default false in legacy and new data. Maintenance and the remote lifecycle toggle do not revoke an independently granted read-only log permission. Null means no owner deadline. A server may remain assigned for connection details while every action and log read is denied. No player IDs are required. Save secret material through Windows-protected storage, outside the repo.
- Distinguish Process running, Server ready, server-reported online players, local game ports, the local Friend-control listener, and an authenticated Friend heartbeat. A local listener, process, or count reply is not a public route or proof of a particular Friend join.
- A saved Friend Host endpoint may be checked from Friend mode; it must display Unknown when the public route or Host cannot be verified. Host mode may show the latest authenticated heartbeat for each paired Friend.
- Host Settings includes a compact owner-only **Preflight & diagnostics** view, also linked from the Attention Center. Per selected server it composes the saved configuration, canonical managed-run state, registered-driver readiness/player observation, declared local-port evidence, and latest authenticated assigned-Friend heartbeat. Shared checks compose the companion listener, latest owner-requested outside TCP result, local-data recovery, and update state. Opening or refreshing diagnostics never invokes a lifecycle action. Every listener or port result stays explicitly local or TCP-only evidence and never becomes public reachability, a successful game join, save integrity, or lifecycle authority.
- Host **Connection Doctor** presents listener, code address, outside TCP route, authenticated Friend heartbeat, local game readiness, and real game join as ordered but independent evidence. Its local **Test with a Friend** session can notice only a fresh heartbeat and server-reported count transition; the two people must still confirm the intended join and a recognizable saved change. The fingerprint-bound **Acceptance Recorder** stores only explicit owner confirmations and invalidates their current credit when the game/world/path/port/route configuration changes. Friend mode separately shows saved access, Host TCP, pinned identity, device access, protocol, assignment, and supported fixed game-endpoint stages, and can copy only a redacted report. Neither doctor probes arbitrary addresses or changes firewall, router, DNS, or private-network policy, and neither upgrades its signals into automatic external certification.
- The owner may copy or download a bounded UTF-8 JSON support report with a fixed safe filename. It includes app/protocol/schema/staging state, safe high-level settings, typed diagnostics, bounded redacted activity/operation summaries, and log metadata only. It excludes credentials and hashes, pairing/invite codes, passwords, protected blobs, raw scripts or arguments, full private paths, IP addresses/endpoints/certificate material, player/chat identity, raw logs, worlds, and environment variables.
- The selected Host server has a compact **Sessions** view over the newest bounded archived exact runs. New summaries show only authoritative run/lifecycle evidence: known start/end and duration, Ready observation, typed outcome, crash-recovery scheduling, trusted server-reported last/peak counts, and rolling-backup result. Legacy gaps remain Unavailable. Player observations do not identify a player or prove a join, save, or world integrity. This history is not exposed in Friend mode.
- The selected Host server also has a **Players** workspace for the current trusted count, source, freshness, countdown reason/deadline, saved Host/Friend added time, and recent count-only transitions. It does not retain identities or infer a join. The Host-only **World Safety Center** reports retained backup size/free space, supports Offline manual checkpoints and read-only manifest verification, hash-verifies owner-selected vault copies, rehearses restore in disposable scratch storage, and offers Safe restart as graceful Stop → successful offline checkpoint → Start. A failed checkpoint leaves the server Offline. No Friend backup endpoint exists.
- The Attention Center surfaces bounded storage warnings; CPU count and process memory remain informational and never authorize lifecycle work. After an interrupted app session, the app reattaches only to an exact recorded process or offers an explicit Resume action through normal Start checks, never an automatic game launch. Update replacement requires a verified bounded same-user state checkpoint and labels publisher trust honestly; unsigned release builds remain GitHub-digest-trusted until the owner supplies a signing certificate.

## Out of scope for v1

Commercial or cloud servers, billing, a public web dashboard, third-party binary plugins, provider provisioning, automatic DNS/router/firewall changes, mobile or console companions, general scheduling, cloud time services, and invitations with arbitrary access-expiry policy are out of scope. The local Custom game manager is not a plugin loader: it stores three explicit Host-owned scripts and tracks the long-running Start wrapper. Script-reported players are display-only by default. An exact configuration becomes eligible for guarded remote lifecycle actions only after contract-v2 probes and the Host-only live save/restart certification succeed; this is owner-certified control, not official game support. No Friend request can supply a script or command. The Valheim friend join/save/restart gate remains required.
