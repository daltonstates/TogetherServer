# TogetherServer 0.3.3.2 prerelease

Owner authorization, 2026-10-22: publish a new GitHub prerelease numbered
`0.3.3.2`, after merging all completed work to `main`. Keep the existing
`v0.3.3.1` assets and stable/latest release unchanged.

## Main integration

The completed shared-hosting branch was fast-forwarded into `main` and pushed
before the release version was changed. Both local `main` and remote
`refs/heads/main` were verified at
`bb5fd01775f2c6bb864d552eda0a8f87ceecf491`. This includes the 25 commits after
the former main `5bf26f79102f0545b3906f9ebedf371c66e7ec35`, the published
0.3.3.1 implementation, its verification fixes, and the final Host locally
entry/Play corrections. Older mockup-only branches are historical review
artifacts, not additional product changes to merge.

## Scope and verification

- One original-Host setting allows permitted friends to host. Verified save
  synchronization and newer signed descendant selection are automatic.
- Friends see a labeled **Host locally** action. Full checks begin after the
  click, with guided next steps and explicit network confirmation before Start.
- **Open game** and **Stop server** have equal dimensions. The helper sentence
  between them is removed.
- Application, UI manifest/lockfile and installer default are `0.3.3.2`.

The prior implementation's evidence is recorded in
[Host locally delivery](40-HOST-LOCALLY-ENTRY.md). Its passes apply to its exact
0.3.3.1 candidate. The fresh 0.3.3.2 candidate is compiled from merged `main`
at `72bb9067627c866a74eb26b44e4bec61c4c15279` in
[Windows run 39796156022, attempt 1](https://github.com/daltonstates/TogetherServer/actions/runs/39796156022).

The original tamper assertion required `State == "Error"` after turning global
sharing off. Automatic signed consent withdrawal can legitimately take
precedence as `State == "Consent off"`, while local status still hashes every
payload and rejects damage. The check now waits for withdrawal before mutation,
requires the intact copy to remain verified, then requires the tampered copy to
have no verified version and an explicit integrity error. It also requires the
corrupted bytes to remain different (preventing a repair from satisfying the
assertion) and both the immutable Host publication and original Host world to
retain their signed/known hashes. Signed receipt and revoked-roster checks stay.
The original failure remains failed. Only check code changes; product source,
the 0.3.3.2 EXE and installer remain frozen.

A focused hosted continuation is prepared to verify the corrected transfer
journey and seven previously unattempted stages against that same candidate.
Its receiver verifies the original run/source, pinned candidate and report ZIPs,
all 19 exact retained passed checks and the original failed twentieth check.
It refuses product/build changes after the compiled source. No successful
stage is repeated, and all eight continuation outcomes are collected explicitly.
Local check compilation passed with zero warnings/errors; workflow YAML and
PowerShell blocks parse.
