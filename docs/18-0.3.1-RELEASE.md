# TogetherServer 0.3.1 release

Date: 2026-10-09. Status: candidate preparation; hosted Windows acceptance and publication pending. The owner authorized creation of 0.3.1 after pushing `main` at `976000e`. Do not interpret this status as a published release or completed visual audit.

## Changes and compatibility

This release includes the unreleased work since `v0.3.0`: signed server chat and notices, protected/named backups, pre-join game requirements and fixed client-opening/manual fallback, guided game settings, local runtime summaries, shared-save workflows with explicit permissions, diagnostics and recovery, and the Host/Join/backup/header UI changes. Real-game live save remains disabled pending its per-game acceptance; Minecraft support and Factorio/Terraria preview boundaries remain unchanged.

Both the tagged 0.3.0 and current app use companion protocol 3. New peer features use advertised capabilities; older peers do not gain those features. Mixed-version code inspection is not packaged acceptance. The candidate's dedicated Windows job must verify 0.3.1 Host / published 0.3.0 Friend and published 0.3.0 Host / 0.3.1 Friend: authenticated/pinned pairing, exact role versions, assigned status, remote Start/Ready, positive-count Stop denial, fresh-zero graceful Stop, paused-control status, assignment enforcement, saved-access restart and revocation. It uses the published 0.3.0 EXE with SHA-256 `e2741b7425c497a7850bc95b5b844a4503099bf6a575484476b4a37330cdce8e` and synthetic loopback fixtures only.

Upgrading local state advances storage schema 2 to 4 and pairing schema 2 to 3. The old executable cannot open the migrated directory; restoring `.previous` alone is not a data rollback. Before release, the actual published 0.3.0 parent/new-helper handoff must preserve disposable settings, migrate its source marker and retain the exact old EXE. This acceptance does not mutate production or a real world.

The release review found that the new helper rejected 0.3.0's schema-2 checkpoint. The fix adds an explicit helper-only validation mode accepting supported source schemas 2–4, requiring a forward target version, previous EXE binding, matching explicit source/checkpoint schema markers and all existing root/hash/name/size/tamper checks. Current-app checkpoint creation/handoff still requires the current schema. Pure checkpoint regressions and both the existing same-candidate helper smoke and actual old-to-new handoff remain required.
