# Implementation order and acceptance

Keep the project small and deliver working vertical slices. Start implementation in the new chat; these documents are the handoff, not the implementation.

## Slice 1 — Local Host app and GUI

- Create one Windows .NET 10 app that shows bundled React/TypeScript assets in its own window over a loopback-only local API, with a clear Host/Friend mode switch. Build and publish without requiring Node at runtime.
- Add local settings for an approved server executable/profile, maximum concurrent managed servers (default 1), idle minutes (initially disabled), and remote-control disabled state. Keep secrets and worlds outside the repo.
- Implement fixed local Start, Stop, Health, and explicit empty-port-conflict replacement actions with a small purpose-built synthetic process fixture. Verify duplicate Start, one-writer-per-world, max count, named port conflicts taking precedence over the generic limit, process identity, crash/restart Unknown, and that Stop never kills an unrelated process.
- The GUI must show actual state, pending actions, and errors. Do not label a fixture or running process as a real Valheim server. This slice is accepted only after a Windows build, meaningful process tests, and a served React GUI check.

## Slice 2 — Friend mode and public-control protocol

- Add persistent owner-created server codes, pinned Host TLS identity, Friend outbound heartbeat, saved Host address, explicit per-friend server assignments, per-server Start/Stop/Extend permissions with global defaults, and typed remote actions. A code remains active until deliberately replaced and initially grants only its encoded server; every PC receives separate revocable access. Only the loopback owner GUI may approve a waiting PC or reassign a connected PC to zero, one, or several current saved profiles. Use one small HTTPS listener; the Host GUI remains loopback-only.
- Implement the owner remote-control toggle and notice. Disabled remote Start/Stop must fail server-side immediately; status/heartbeat still communicates Disabled. Revoke one device and prove its credential stops working while another remains valid.
- Test retry/idempotency, invalid token, wrong certificate, wrong effective per-server permission, mixed global permission state, denial for valid saved access against an unassigned server, zero/one/multiple Host reassignment, unknown profile rejection, stale/Unknown heartbeat, Host restart, and at least two instances on separate local processes. Exercise a code after long elapsed time and multiple PC connections, optional approval, deliberate code replacement with old-access removal, per-PC removal, rename, reachable and offline Forget, maintenance, redacted activity, and fixed timer-extension limits. Older unscoped credentials must migrate with no server access until the Host assigns them. These tests do not prove public Internet reachability.
- Every exact release candidate must pass the dedicated core remote journey: separate packaged Host and Friend processes, pinned authenticated connection rather than port-open inference, remote Start to Ready, positive-player Stop denial, fresh zero-player graceful Stop, explicit closed-listener classification, and reconnect with the same saved pin, credential, assignment, and permissions after both apps restart. Missing, skipped, or failed core-journey evidence blocks release. This loopback fixture remains separate from the real Friend-network and game-join gate.
- Test nullable per-device owner access deadlines independently from renewable credential expiry. Cover exact UTC equality with an injected clock, already-loaded device objects, immediate expiry/extension/clear, persistence across Host restart, and precedence with approval pending, revocation, credential expiry, assignments, and permissions. Every authenticated companion route—including status, heartbeat, Start, Stop, Restart, replacement, timer extension, player refresh, renewal, operation status, endpoint recovery, self-revoke, and server logs—must return typed `AccessExpired` without journaling or executing lifecycle work and without removing the credential or assignment. Test the loopback-only setter's fixed durations, bounded UTC timestamp, malformed/ambiguous/past/distant/unknown/revoked/Friend-mode denials, non-secret activity/audit records, and unchanged per-device throttling.
- Test storage schema 1 to 2 migration with real protected pairing data and preserve device identity, invite lineage, assignments, permissions, and renewal receipts. Prove a schema-1 reader rejects the v2 marker before pairing access, the v2 reader completes an interrupted marker-first migration, and an unknown newer schema is rejected without rewriting it. Document that rollback needs a full matching pre-migration backup; changing only the marker is not supported.
- Test the everyday GUI path: new or copied world, world name and password in one compact setup, direct Start, persistent server-code creation/copy/reuse/replacement, immediate listener enable/disable, per-PC access removal, and action-first Host/Friend cards. Prove that a missing code in a successful response or a local request that takes more than 20 seconds becomes a visible retryable error instead of an endless loading message. Verify the custom native minimize, maximize/restore, close, and important-event tray notification paths. Verify 1440x900, 768x1024, and touch-enabled 390x844 layouts without horizontal overflow. TS1 and TS2 per-device invites remain readable until expiry.
- Test remote Stop with disposable Valheim, Minecraft Java, and Minecraft Bedrock protocol fixtures: expose zero and positive online-player counts, deny positive and unknown counts, recheck after initial approval, and allow a permitted Friend Stop over HTTPS only at zero. This is parser, process, and policy evidence, not proof of a real game join or save.
- Test the server-log backend and viewer independently: legacy and new View logs permissions default false; Start/Stop does not imply access; global mixed and per-server exceptions persist; assignment and the effective exact-profile grant are rechecked before and after every asynchronous authenticated read; unassignment, permission removal, credential revocation, and owner expiry deny returned records. Prove `server-logs-v1` advertisement and old-peer refusal, the local Host and Friend GET header gate, protected-credential Friend proxying, declared and chunked response-byte caps before JSON decoding, cancellation, bounded limits/filters/client history, HMAC cursor tamper/fabricated-offset/cross-run/cross-service rejection, visible-only single-flight polling, pause/resume and manual refresh, transient-failure cursor preservation, atomic run-change/stale-cursor reset, Host active/latest-retained selection, Friend active-exact-run-only denial for ended history, owned-path enforcement, 30-day startup/read/create retention, arbitrary-path impossibility, control/ANSI and CR/LF handling, bounded decoded timestamps/strings, secret/address/identifier/name/path redaction, typed missing/ended/unsupported/error states, and no Custom remote logs. Display logs must not enter readiness, occupancy, countdown, or Stop authorization.
- Test the owner diagnostics and support export independently. Prove both fixed-input GET routes require `X-TogetherServer-Local: 1`, reject query/body/arbitrary target or output-path input, and reject Friend mode. Verify selected-server and shared checks reuse canonical snapshots, registered-driver validation, existing local port/listener diagnostics, authenticated heartbeat receipts, recovery/update state, and only the latest owner-requested route result. Assert honest local/TCP-only evidence labels, offline usefulness, no lifecycle side effect, neutral/orange/error presentation with no green positive state, fixed Copy/Download filename and errors, deterministic redaction of representative secrets, private paths, addresses, endpoints, certificates, player/chat content and log lines, per-field/count/UTF-8 size bounds, and preservation of existing Host/Friend controls. Browser-unavailable runs may prove component behavior and production bundling but must mark visual/viewport acceptance skipped.
- Test archived session summaries independently: confirmed graceful Stop with rolling backup completed, failed, and off; failed/unconfirmed Stop without a successful archive; unexpected exit after Ready; exit before Ready; failed recovery before Ready; and owner archival of an exited record. Prove exact-`OperationId` trusted last/peak count accumulation, Unknown never becoming zero, Host-restart persistence, immutable one-summary-per-run behavior, legacy Unavailable projection, and unchanged 30-day/500-entry retention. The Host-only GET must require `X-TogetherServer-Local: 1`, reject Friend mode and every query except a 1-through-20 limit, and expose no sensitive fields. Strict TypeScript decoding and compact Sessions-tab tests must cover loading, empty, complete, legacy/incomplete, and error states with no green positive styling or game-join/save claim.
- Test both Connection Doctors as strict evidence ladders: a local listener cannot pass outside TCP, outside TCP cannot pass authentication, a heartbeat cannot pass game readiness, and a count change cannot automatically pass a real join or saved-world check. Friend mode must keep saved access, Host TCP, pinned identity, device access, protocol, assignment, and the fixed game-endpoint check separate; it may probe only its current saved profile through existing fixed requests. Copied reports must exclude codes, credentials, pins, endpoints, addresses, IDs, names, and player identity. The coordinated Host workflow may use only post-start heartbeat/count evidence plus explicit human confirmations and mutate no network policy. Acceptance Recorder tests must prove records are fingerprint-bound, become stale after configuration change, persist no raw sensitive setup details, and never become authorization, occupancy, or automatic acceptance. A real Friend PC on the intended route remains the external gate.
- Test permission presets and Attention routing independently. Each reviewed preset must atomically send all four permission values with no scope, clear per-server exceptions through the existing backend contract, and map mixed values to Custom. Attention grouping must retain the newest event, count repeats, and map only reviewed categories to fixed workspace destinations; event text must never become a command, route, profile selector, or arbitrary URL.
- Test the Players workspace, pane recovery, and shared contract fixture. Strict decoding must cover observation source/time, total and Friend-added shutdown minutes, backup capacity, and hosting-power state. Count history must exclude identities. An exception in logs, sessions, diagnostics, connection help, players, world safety, recovery, or Attention must leave the rest of the app usable with a retry action and no server mutation. Both .NET and TypeScript must consume the checked-in Host snapshot fixture so nullability/name drift fails a source check.
- Test World Safety Center and resilient hosting with disposable files/processes. Manual backup must require definite Offline, use only the driver's reviewed save root, show retained/free bytes, verify every manifest hash without changing the live world, and detect payload tampering. Vault copy must use only a native owner-selected destination, reject app/live overlap and linked child folders, re-hash the transfer, and retain the local copy. Restore rehearsal must use disposable app-owned scratch, fully verify, clean up, and leave the live world byte-identical. Safe restart must prove exact graceful exit, complete a rolling or manual offline checkpoint, start only afterward, and remain Offline on checkpoint failure. Startup recovery must distinguish clean exit, exact reattachment, definitive exit, and ambiguity; require deliberate Resume; and never start a game automatically. Storage/free-space warnings must remain bounded and CPU/RAM readings informational only. A fake power adapter must prove activate-only-while-exact-process and clear-after-Stop without changing the test machine's power policy. Resume simulation must invalidate observations/deadlines, preserve exact-run added time, publish Unknown before fresh evidence, and never issue Start or Stop. Real Windows sleep/resume, installed-binary behavior, and valued-world restore remain external acceptance.
- Test explicit port-conflict replacement with a Start-only Friend assigned only to the requested profile: ordinary Start reports the other saved name and shared ports without stopping it; positive/Unknown counts and any saved Host/Friend-added shutdown time deny replacement; an unextended zero-player conflict receives a second count check, graceful Stop, and then launches the requested profile without granting general Stop or exposing the other join address.
- Test the game-driver registry with Valheim, Java, Bedrock, Factorio preview, an isolated synthetic driver, and fail-closed handling of unknown kinds. For each real driver, verify its declared ports, start-time conflict check, local listener diagnostics, readiness evidence, online-player count, and graceful stop. A local open port or count reply must not be recorded as public reachability.
- Test the explicit Custom driver separately: scripts stay Host-only and Windows-protected; the long-running Start wrapper retains verifiable process identity; Status/players uses bounded strict contract-v2 JSON and timeouts; local Stop requires the wrapper to exit; uncertified or mismatched counts never authorize lifecycle actions; and the complete owner certification proves zero/positive/zero, final-zero race protection, wrapper exit, restart, saved-change confirmation, persistence, and invalidation. Certified Custom remains owner-certified compatibility evidence, never official support for the selected game.

## Slice 3 — Real Valheim and friend smoke

- Use the owner-installed, owner-approved Valheim Dedicated Server. Verify the selected build, actual startup/readiness, game ports, graceful Ctrl+C-equivalent stop, save folder, and recognizable world change across stop/restart against [upstream guidance](https://www.valheimgame.com/support/a-guide-to-dedicated-servers/). Do not download or accept terms on the owner's behalf.
- Verify Valheim's real player count across zero, one, disconnect, and unavailable states, including the owned-log fallback on a private non-Crossplay server whose local query is silent. Confirm that partial log events remain Unknown and that Crossplay does not use the unvalidated fallback. A Friend Stop must be denied at one or Unknown and recheck zero immediately before Ctrl+C. Automatic shutdown must cancel its shared Host/Friend deadline at one or Unknown while preserving already-added minutes for the current managed run; a later exact zero starts a fresh base window plus that saved time. Verify Host and permitted Friend additions while occupied, the per-run Friend maximum, reset on Stop/restart, idle-wait change, or disabling automatic shutdown, and the final exact-zero recheck before Ctrl+C. No Host/Friend client-process setting or Friend heartbeat may gate the countdown. Keep automatic shutdown off for valued worlds until its separate real idle/save acceptance passes.
- With the owner's explicit approval, test the chosen public-IP control port from an actual Friend network and the game join path separately. Do not change public router/firewall/DNS settings automatically. A localhost test is not a public reachability pass.
- Record a real Friend start/stop permission test, disable notice, actual game client join, save, stop, restart, idle behavior, and Host recovery. Keep any missing external test marked **blocked**, not passed.

## V1 acceptance gate

V1 is accepted only when the owner can run the bundled Host app; every Friend requesting controls uses the bundled Friend mode; remote Start/Stop and disable/revoke work over the deliberately selected direct, private-mesh, or advanced route; max-concurrent and one-world writer rules hold; no remote or automatic action treats an unknown player count as zero; Valheim starts, reports a real player transition, accepts a real friend, stops gracefully, and preserves a recognizable world change through restart. Record exact versions, commands, screenshots/log excerpts with private details removed, and pass/fail/skip counts.

Owner access-expiry UI acceptance requires the Host editor to preserve assignments and permissions, expose only the reviewed presets/Clear plus a bounded explicit UTC Advanced path, show the exact local conversion before Save, reload canonical device state on success, and keep pending/success/error states accessible without introducing a green-positive visual. Friend mode must render typed `AccessExpired` as owner-ended access while retaining the saved connection, not as disconnection, revocation, or credential expiry. Focused component/contract coverage and an attended supported-viewport review are required locally. A real Friend PC must still confirm the expired, extended, and cleared states over the selected network route; local HTTPS instances do not satisfy that external gate.

## External gates and data protection

The owner must handle game terms and deliberately initiate any Minecraft installation in the app, public router/firewall approval, credential exchange, and the real Friend/client test. Valheim installation remains an owner/Steam action. Continue independent code and local fixture testing while those are pending. Never delete or overwrite a real world for a test. Create isolated synthetic data under ignored `local-data/` and leave the owner's existing game install and worlds alone.

For candidate testing beside a stable install, use only the marked development/staging instance: the packaged `TogetherServer DEVELOPMENT.exe` selects it automatically, while `--staging` remains available to reviewed launchers and checks. Acceptance requires a direct filename-based launch plus simultaneous production/staging process evidence with distinct data and loopback/control ports, rejection of equal/nested/pre-populated roots, rejection of production save paths and existing-world import, no Windows startup or automatic-update mutation, and an unchanged fake production-world marker. Real Friend acceptance still requires the staging Friend app on another PC/network to authenticate to TCP 5132 (or its explicitly chosen staging port), followed by a separate real game join to the staging game's ports. Local synthetic evidence does not satisfy either external gate.

Installer acceptance uses a disposable per-user destination and data root only when no installed TogetherServer copy is present. Verify that the installed executable is byte-identical to the release candidate, the Start-menu shortcut targets it, Windows registers an uninstaller, every setup choice can be skipped, and bounded optional Host/Join, sign-in, and tray choices take effect. Launch the installed app, then uninstall it and prove that its shortcut, registration, executable, and exact startup entry are removed while its isolated data remains. This does not prove Windows Search indexing latency on every PC, Authenticode reputation, game readiness, or Friend reachability.

Update acceptance must prove payload digest verification, optional same-publisher Authenticode enforcement, a visible digest-only/development trust state when no certificate is configured, bounded local-state checkpoint creation, manifest/file tamper rejection in both app and helper, and preservation of the verified previous EXE. A trusted-publisher claim remains blocked until the owner supplies a real signing certificate and an installed signed candidate is verified.

## Minecraft extension gate

Java and Bedrock have separate built-in drivers and explicit display-log adapters. Their fixture checks cover validated settings, TCP/UDP local status responses with online-player counts, positive-count Friend Stop denial, concurrent profiles with separate save folders, exact-run bounded stdout/stderr capture, partial UTF-8, long/interleaved/chatty output, cursor integrity and cross-run rejection, shared Host/Friend sanitization, unrelated-process survival, log-failure isolation, restart reattachment, fixed graceful console Stop, exact exited-helper cleanup after a proven pre-game failure, and unresolved-run retention for live/ambiguous helpers or any possible game identity. Setup checks cover bounded file detection, consent denial, fresh Java/Bedrock installs through synthetic HTTP responses, hashes, archive safety, and existing-world preservation. Before claiming real support for either edition, test an owner-installed server, zero/one-player status transitions, actual Friend join, recognizable world change after Stop/restart, the automatic-shutdown idle window, and the intended network route. Keep automatic shutdown off for valued worlds until that edition passes its real idle and save rule.

## Factorio preview extension gate

Factorio has a separate built-in preview driver. Fixture checks must cover owner-installed executable validation, verified copy-once ZIP import with the source unchanged, managed-path enforcement, separate UDP game/TCP RCON ports, protected RCON authentication, fixed launch arguments, zero/positive/zero player replies, final zero recheck, exact-process `/quit`, backup/vault/rehearsal behavior, and duplicate-import refusal. These checks are synthetic. Before removing the preview label, use an owner-installed Factorio server/client to prove a real join, real player transitions, recognizable save/restart and restore behavior, intended Friend/game routes, and safe idle Stop. Never forward the RCON port, and keep automatic crash restart unavailable until separately accepted.

## Terraria preview and Host move gates

Terraria source checks cover copy-once `.wld` import with the original unchanged, managed-path enforcement, fixed executable/port/world selection, TCP-only listener evidence, unknown player count, and disabled automatic crash recovery. An owner-installed server/client must still prove fixed launch and `exit`, real readiness, zero/positive/zero occupancy, a Friend join, recognizable saved change after restart, and the intended network route. Until a trusted count is implemented and accepted, Friend and automatic Stop stay blocked.

The Host move kit must export a completed hash-verified backup without credentials or game binaries, verify all hashes again when selected on another PC, reject tampering, and leave source and existing destination worlds untouched. The owner installs the game server and copies the payload into a fresh offline save location, then pairs Friend PCs again. A real destination-PC join and saved restart remain external acceptance.
