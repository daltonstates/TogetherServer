# TogetherServer 0.3.2.1 prerelease

Date: 2026-10-18. Status: **preparing; not yet published**.

The owner authorized a GitHub prerelease and only a fourth-component increment:
`0.3.2.0` to `0.3.2.1`, tagged `v0.3.2.1`. The existing stable release remains
`v0.3.2`. Application, UI manifest/lockfile and installer versions are aligned.

## Included changes

- Per-PC prerelease update enrollment, default off, with explicit Update and
  restart. Three- and four-part numeric versions retain their identity through
  selection, release links, reminders, payload validation and checkpoints.
- Required profile-name setup on new installations and upgrades, shared names
  between Host and Join, and a reusable feature-setup flow.
- Updated Host/Join navigation, responsive layouts, world protection/sharing
  editors, dismissible notices and revoked-PC/Host management.
- Peer shared-world exchange and explicit solo recovery into a separate history.
  Receiving and resharing remain separate permissions. Real live-save capture
  still requires installation-specific acceptance.
- Private signed-test copy writers support long Windows paths through the same
  leased-parent native open used for other snapshot operations, preserving
  exclusive access and reparse/type/hard-link refusal.

Companion protocol remains 3, pairing schema 3 and the current storage schema 5.
Existing schema 1-4 app data migrates marker-first to schema 5. Older binaries
reject that marker; rollback requires matching pre-migration recovery material.
This preview uses normal production app data and is separate from staging.

## Validation and publication

Local checks are limited to code-only verification, JSDOM, formatting and static
artifact inspection. App/process/browser/desktop/update/installer checks run
only on dedicated hosted Windows runners with the workflow's explicit opt-in.
No production app, credential, world or installation is used for testing.

The release workflow builds one source-stamped candidate, verifies those same
bytes in every lane, and packages the installer only after acceptance. Published
0.3.0, 0.3.1 and current-stable 0.3.2 binaries are hash-pinned for both Host/Friend
role directions and actual update handoff. Release publication must use the
verified portable, installer and their adjacent SHA-256 files, followed by fresh
unauthenticated public-download checks. Exact source, run, results and hashes
will be recorded here when verification completes.
