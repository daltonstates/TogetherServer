# 0.3.3.6 prerelease

Owner authorization, 2026-10-23: hide **Host locally** when shared hosting is
not enabled and publish another prerelease. This preview also includes the
permission and Valheim count fixes in [delivery record 46](46-LOCAL-HOSTING-PERMISSION-AND-VALHEIM-COUNTS.md).

## Behavior

The Friend action and card appear only after the current permission response
explicitly allows local hosting. Initial, failed, unavailable and denied
permission checks keep the launcher hidden. An already-open guide can still
show a changed permission or unavailable check without retaining permission to
Start. Re-enabling sharing can restore the entry through ordinary polling.

A valid first signed roster without Receive and EligibleHost grants now reports
the owner's missing permission instead of an endless unknown/retry state.
The original owner enables **Allow friends to host this server** and keeps the
PC approved and assigned. No UI state grants access or bypasses signed history,
local consent, exact-save preparation or the final lifecycle checks.

Valheim's local player-count query retries one silent exchange, and its
non-Crossplay fallback rereads the owned log after the query wait. Incomplete
count replies, incomplete log lines and truncated histories without a count
baseline remain Unknown. Friend and automatic Stop still require a fresh
trusted zero immediately before the graceful action.

## Release verification

Release preparation uses only committed source in a clean checkout. Existing
unrelated connection work in the owner's workspace is retained and excluded.
The version increases only the fourth component from 0.3.3.5 to 0.3.3.6.
Hosted Windows builds one candidate and passes its unchanged bytes to the
functional, browser, compatibility, native and installer jobs. Local work uses
code-only checks and never launches the app, game, browser or installer.

Exact source/run/artifact identities, validation results and publication are
recorded here as they complete. No earlier candidate is relabeled or rebuilt
after acceptance. Published assets remain unsigned unless separately verified.
Native notification, physical-PC routing, real-game count transitions and
recognizable game save/restart evidence remain separate acceptance requirements.

Focused local checks pass all 66 FriendLocalHosting JSDOM cases, file-scoped
lint and 35 pure screenshot-fixture checks. They cover initial, failed, timed-out
and late permission results, enable/withdraw changes, both entry presentations,
profile/connection changes before reset effects and an already-open guide's
disabled Continue action. The hosted browser plan contains 26 cases across
three viewport variants (78 captures), including disabled and unverified
permission on both Play and Shared saves. These local checks launch no browser.
