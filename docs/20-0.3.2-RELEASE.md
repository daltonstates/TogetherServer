## Changes

- Start or Stop is the primary Host action above the server tabs; running-server connection details lead Overview. Create and Join have equal first-use actions, and Friend Play leads with starting, opening the game and connection details.
- Secondary diagnostics and server tools use named disclosures. Players prioritizes the count and empty-server timer. Server tabs use icons and a common inset, including padded Sessions filters and results.
- Chat Sync immediately shows pending feedback and then success or failure. Success feedback is short lived and late results from another server or connection are cancelled.
- Native executable, window and tray icons use embedded multi-size assets rather than a temporary drawing.
- Successful action receipts expire after eight seconds or retire as soon as newer server evidence supersedes them. A Ready server no longer retains the original waiting-for-startup result in its header or Notifications. Friend startup/Stop receipts follow the same rule; pending actions and errors stay visible.

Implementation and source/synthetic evidence are recorded in [the core UX delivery](19-CORE-UX-DELIVERY.md). No lifecycle, process identity, permission, pairing or world-save authority was changed by these UX fixes.

Backend state was confirmed Offline, but the direct manual-backup API can publish a temporary world-copy reservation to a three-second UI poll. Restore review completed within 764 milliseconds, before that UI evidence refreshed, so its offline guard correctly kept Restore disabled. The harness now waits for the selected Host's visible Offline state after Stop and again before reviewing Restore following the backup. Disabled-before-confirmation, enabled-after-confirmation, cancelled Restore and both unchanged-world sentinels remain enforced. Runtime guards and polling were unchanged. All its other verification lanes passed; its overall conclusion remains failure. Publication uses the fresh candidate and complete successful run below.

Packaging waits for all verification lanes and compatibility jobs, compiles the installer around the same verified portable bytes, tests install/uninstall on a disposable Windows runner, and emits four public assets with a source/hash manifest. Publication requires matching source identity, asset hashes and completed acceptance; fresh public downloads are checked again after publication.
