# 0.3.3.8 prerelease

Owner authorization, 2026-10-24: create a new GitHub prerelease for the
[remote-hosting fixes](50-REMOTE-HOSTING-HISTORY-PROGRESS-AND-OWNER-STOP.md).

The app, UI and lockfile advance together to 0.3.3.8. One clean committed source
must produce one immutable Windows candidate. Hosted functional, rendered,
compatibility, native and installer checks consume those unchanged bytes.
Publication is a prerelease with `make_latest=false`; existing releases and
stable/latest must remain unchanged. Public downloads must independently match
the frozen candidate, installer and adjacent SHA-256 files.

## Validation record

Implementation and versioned validation are in progress. Final source, run,
artifact, hash and publication identities will be appended after their checks.
The initial history regression failure is retained as evidence of the repair.
No incomplete or skipped stage is counted as passed.

The final UI suite passes all 1,472 tests in 109 files. All 68 source/synthetic
groups pass after the signed-world enrollment/authorization repair. All 38 pure
renderer fixture tests pass; the focused hosted review plans 31 cases at three
viewport/text-scale variants (93 plans). Local locked restore and solution
compilation pass with zero warnings/errors. These source/fixture results do not

current failed/completed progress while the response remains pending, no spinner
revival and no automatic Start. The signed-history regression initially failed
with the reported verification error and passes after the retained-interval fix.

## First candidate findings

The first candidate, source `8229e1702cfbd94ca97293947d339cc7ac633ddf`, is retained
as diagnostic evidence and is not published. Its main regression suite passed
all 27 stages, and its UI, compatibility, installer, browser, API and rehearsal
results remain evidence of that candidate only.

Hosted shared-hosting checks exposed an additional setup gap: the hosting PC's
remote-control switch considered raw saved Stop grants and missed the original
owner's verified effective Stop right. The final source includes that permission
when enabling controls, keeps the action deliberate, intersects the proposed
profile list, and preserves existing Stop-only pending-invite setup. Seven
real-manager/fake-driver cases cover the owner, member, revocation, exact deadline,
different signed root, removed-profile scope and legacy invite. They launch no
process, listener or certificate creation. A new immutable candidate must repeat
the full hosted gates before publication.

The original hosted failures are retained. Check-only repairs also update old
blanket owner-Stop-denied assertions, avoid a lab-disallowed sharing-management
POST, resolve sidebar navigation by its actual target, and bound screenshot
response/paint and detached-pane waits. These do not relax lab isolation or
turn the initial failed jobs into passes. The unchanged UI passed all 93 final
render plans with 469 screenshots, zero layout findings and five manually
inspected representative screenshots; the final candidate must match those UI
bytes or receive another rendered review.

This preview remains unsigned unless a real configured signing certificate is
available. No publisher or SmartScreen trust is inferred. Hosted notification
delivery/click/navigation may remain blocked by Windows QuietTime; any such
failure must stay explicit and full-native-acceptance flags remain false.

Real two-PC routing, shared-save transfer, game join, exact-zero remote Stop,
recognizable save/load/restart and valued-world acceptance remain separate
unverified checks. No local app is installed, replaced or relaunched to test
this release; no real game or world is used. Update both PCs before retesting.
