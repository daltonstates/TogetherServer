The exact DEVELOPMENT filename / --staging select a separate instance. Confirm
which process, binary, Windows account and root the failed UI actually uses.
Do not dump all environment variables or full process command lines: they may
contain private values. Inspect only the specific app/instance fields needed.

Windows protection uses DPAPI DataProtectionScope.CurrentUser. A protected blob
copied to another PC/account generally cannot be decrypted there. Do not move
the laptop's data/keys to the desktop or into Git for diagnosis.

CRITICAL: LocalData is not a harmless read-only inspector.
- Its constructor opens host.lock exclusively, performs recovery/schema work
  and prunes logs.
- LoadProtected can quarantine undecryptable/invalidly encoded state and return
  null. LoadProtectedJson has additional quarantine/recovery behavior.
- Chain Ready/Reads can recover pending entries or migrate old protected state.
- Some signing-key helpers create keys if missing.
Do not instantiate these helpers against the live production root merely to
"look". Prefer bounded raw, non-mutating reads and same-user DPAPI decode into
memory without key export. Review called code first. An existing example of
avoiding LoadProtected's side effects is ReadLocalReceiptObservation in
FriendLink.SharedWorlds.cs; it is an example, not a ready-made history inspector.
